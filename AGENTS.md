# T-Bank SRE — правила репозитория

Учебный монорепозиторий: `services/taskboard` — одно приложение для всех домашних
работ; `homework/NN` — условие, отчёт и материалы конкретного задания;
`docs` — общие решения; `scripts` — команды подготовки артефактов.

## Процесс

- Trunk — `main`; пока удалённая основная ветка называется `master`, она выполняет роль trunk.
- Ветки `feat/<task>` / `fix/<task>` живут одну небольшую задачу (желательно менее дня).
- Изменения через небольшие PR, проверки должны проходить; squash merge, затем удалить ветку.
- Не создавать постоянные develop/release-ветки. Сдачу фиксировать тегом `hwNN-vN`.
- Сначала короткий план, затем код, проверки и актуализация отчёта. Не изменять чужие проекты.
- Не коммитить .env, секреты, зависимости, бинарники и архивы. Архив генерируется `make archive`.

## Код (адаптировано из neformeet)

- Go: `gofmt`, `go vet`, явные зависимости, `context.Context` и таймауты у БД/HTTP;
  корректная обработка SIGTERM/SIGINT; структурные логи stdout без секретов и SQL-параметров.
- HTTP-хендлеры, правила валидации и SQL разделять по файлам. По мере роста — отдельные
  presentation/services/infrastructure пакеты с интерфейсами у потребителя; не добавлять DI-генерацию для нескольких функций.
- SQL параметризованный; миграции версионированы, применяются отдельной командой.
- React: простые функциональные компоненты, hooks, без необязательного UI-фреймворка.
- Конфигурация развёртывания только через env (требование 12 факторов); не переносить
  конфиги/secdist/Lockbox или сервисную бизнес-логику neformeet.
- Новую логику покрывать содержательными тестами. Проверки: `make check`, после запуска
  PostgreSQL и приложения — `make integration`. Для инфраструктурных изменений проверить Compose.
- Отчёт должен описывать фактическое поведение и ограничения, не обещать непроверенное.

## Kubernetes (домашняя работа 02)

- Манифесты в `deploy/k8s`, управление — `scripts/k8s.sh` и цели `make k8s-*`.
- Использовать отдельный профиль `tbank-sre-hw02`, namespace `taskboard-lab` и
  явный `--context`; не применять учебные манифесты в другие кластеры.
- Пароль генерируется в `homework/02/.env`; в Git/архив входит только шаблон Secret.
- После изменений манифестов: `make k8s-validate`, deploy, scale и CRUD через Service.
- `make archive-hw02` требует настоящий скринкаст <=7 минут; не подменять видео
  анимацией команд или текстовым сценарием. Видео и ZIP не коммитить.

## Мониторинг (домашняя работа 04)

- Метрики Go — `internal/taskboard/metrics.go`, отдельный внутренний listener 9090.
  Не открывать `/metrics` на API-порту и не добавлять пользовательские ID в labels.
- VictoriaMetrics Single ставится официальным Helm-чартом 0.49.0; values/RBAC в
  `deploy/monitoring`, команды `make monitoring-*`. Встроенный scraper использует pod SD.
- PostgreSQL exporter — sidecar на 9187, пароль только через Secret.
- Проверять counters на успешных операциях и 400/404, OpenMetrics, fresh samples
  в TSDB и discovery при изменении числа реплик. Рантайм-метрики не должны зависеть от БД.
- `make archive-hw04` включает настоящий скринкаст, отчёт, все исходники/манифесты
  и Helm render; рабочие секреты и сгенерированные бинарные артефакты не коммитить.

## Логи (домашняя работа 03)

- Общая JSON-схема в `internal/logging`: timestamp, level, message, service.name.
  HTTP добавляет request.id, method/path/route/status/duration_ms; тела, query и секреты не логировать.
- VictoriaLogs и Vector — `deploy/logging`, namespace logging в том же учебном minikube.
- Vector читает только контейнер taskboard в taskboard-lab; не расширять сбор на другие проекты.
- Проверять свежую доставку по request.id и 4 LogsQL-запроса; скриншоты должны быть из настоящей vmui.
- В отчёт и архив включать четыре PNG и Helm render; рабочий kubeconfig/.env и зависимости не коммитить.

## SLI/SLO/SLA (домашняя работа 05)

- Формулы и ссылки vmui — `scripts/slo_queries.py`; различать demo 1m и целевое окно 30d.
- Пробер Go читает UI/API через Service, не меняет БД; порт 9091 только внутри кластера.
- Пустой request denominator не считать 100%; resets обрабатывать до суммирования реплик.
- Учебные отказы только через env DEMO_*, по умолчанию выключены; после демонстрации вернуть healthy.
- `make archive-hw05` требует настоящую запись графиков и проверенные фазы healthy/slow/errors/recovery.
- Нагрузку запускать отдельным временным Job; не менять чужие данные и кластеры.

## Grafana (домашняя работа 06)

- Helm values и исходные JSON — `deploy/grafana`, экспорт из работающей Grafana —
  `homework/06/dashboards`; команды `make grafana-*`, namespace monitoring.
- Data source VictoriaMetrics имеет UID `victoriametrics`; запросы выполняются
  сервером Grafana через Service, не напрямую браузером к экспортерам.
- Формулы SLI брать из `scripts/slo_queries.py`; demo 1m и формальный SLA 30d
  показывать отдельно. При недостатке истории не подменять результат на 100%.
- PostgreSQL dashboard 9628 импортируется из сохранённого JSON; сохранить
  оригинал, checksum и описание адаптации к текущему exporter/PostgreSQL.
- Проверять настоящие запросы через Grafana, скриншоты и видео с интерфейсом.
  `make archive-hw06` включает экспорт JSON, отчёт и настоящий скринкаст.
- Пароль администратора только в Secret/локальном .env, доступ снаружи — loopback
  port-forward. После записи вернуть healthy и удалить временный нагрузочный Job.
