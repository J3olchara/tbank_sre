# T-Bank SRE — правила репозитория

Учебный монорепозиторий: `services/taskboard` — одно приложение для всех домашних
работ; `homework/NN` — условие, отчёт и материалы конкретного задания;
`docs` — общие решения; `scripts` — команды подготовки артефактов.

## Процесс

- Trunk — `main`; пока удалённая основная ветка называется `master`, она выполняет роль trunk.
- Ветки `codex/<task>` / `feat/<task>` / `fix/<task>` живут одну небольшую задачу (желательно менее дня).
- Изменения через небольшие PR, проверки должны проходить; squash merge, затем удалить ветку.
- Не создавать постоянные develop/release-ветки. Сдачу фиксировать тегом `hwNN-vN`.
- Сначала короткий план, затем код, проверки и актуализация отчёта. Не изменять чужие проекты.
- Не коммитить .env, секреты, зависимости, бинарники и архивы. Архив генерируется `make archive`.

## Код (адаптировано из neformeet)

- Go: `gofmt`, `go vet`, явные зависимости, `context.Context` и таймауты у БД/HTTP;
  корректная обработка SIGTERM/SIGINT; структурные логи stdout без секретов и SQL-параметров.
- HTTP-хендлеры, правила валидации и SQL разделять по файлам. По мере роста — отдельные
  presentation/services/infrastructure пакеты с интерфейсами у потребителя; не добавлять DI-генерацию для нескольких функций.
- SQL параметризованный; миграции версионированы, применяются отдельной командой.
- React: простые функциональные компоненты, hooks, без необязательного UI-фреймворка.
- Конфигурация развёртывания только через env (требование 12 факторов); не переносить
  конфиги/secdist/Lockbox или сервисную бизнес-логику neformeet.
- Новую логику покрывать содержательными тестами. Проверки: `make check`, после запуска
  PostgreSQL и приложения — `make integration`. Для инфраструктурных изменений проверить Compose.
- Отчёт должен описывать фактическое поведение и ограничения, не обещать непроверенное.
